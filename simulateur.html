Décisions humaines de cette fabrication

    Orchestrateur déterministe

    Le workflow est une machine à états : mêmes entrées, mêmes états, mêmes contrôles, mêmes outils. Seul le contenu produit par les modèles varie.

    Rejeu

    Même entrées, même chemin d'état. Le contenu généré, lui, peut différer d'une fabrication à l'autre.

    Ce que le modèle ne décide jamais

    • L'enchaînement des états et les conditions de transition.
    • Les outils disponibles, les droits et le budget (autorité statique, hors bande).
    • Le routage vers un modèle selon la classe du projet.
    • Le go, l'approbation de la MR, l'arrêt d'urgence : toujours un humain.

    Journal d'audit (simulé)

      Glossaire

      Modèle d'IA
      Le moteur de langage qui lit et écrit du texte et du code (exemples : Claude, Gemini, Codex, Mistral, Kimi). Il reste hors de la cellule. PHARE n'est lié à aucun d'eux.
      Agent
      Programme qui utilise un modèle pour agir : lire des fichiers, lancer des tests, écrire du code. Il travaille dans la cellule.
      Cellule isolée (sandbox)
      Espace fermé où l'agent travaille. Pas d'internet libre, quel que soit le niveau de confidentialité. Deux niveaux de blindage : N2, et N3 pour les projets très confidentiels.
      Passerelle
      Le seul passage de la cellule vers le modèle : surveillée, avec une clé temporaire plafonnée. Niveaux C0 à C2 : modèle cloud ou interne. Niveau C3 : modèles internes seulement.
      Recherche côté fournisseur
      Certains fournisseurs savent, une fois la requête reçue, chercher sur le web ou exécuter du code depuis leurs propres serveurs : la cellule ne le voit pas. PHARE refuse ces options : la passerelle rejette toute requête qui les demande. Le modèle répond avec ce qu'il a reçu.
      Niveau de confidentialité (C0 à C3)
      Fixé par projet, jamais abaissé automatiquement. Il décide des modèles permis, du blindage de la cellule et du nombre d'approbateurs.
      Contrôle d'entrée (préflight)
      Vérification du dossier avant toute fabrication : complet, sain, données sensibles, niveau, droits.
      Dossier figé et signé (snapshot)
      Version exacte de ce qui sera fabriqué (tickets, maquettes, plan). Le go du chef de projet est lié à elle.
      Fabrication (run)
      Une exécution complète de l'usine, du go à la demande de fusion.
      Banc d'essai (mutation)
      On introduit volontairement de petits défauts dans le code pour vérifier que les tests les détectent. Des tests qui ne voient rien ne prouvent rien.
      Analyse de sécurité (SAST)
      Lecture automatique du code à la recherche de failles connues.
      Dans le doute, on s'arrête (fail-closed)
      Sans autorisation claire, l'usine refuse. Elle ne continue jamais par défaut.
      Demande de fusion (MR)
      Proposition de changement soumise dans GitLab, avec son dossier de preuves. Un ingénieur la relit et l'approuve.
      Escalade
      L'usine ne peut plus avancer seule : elle appelle l'équipe plateforme (le « mécanicien »), qui diagnostique, relance ou arrête.
      Règles communes (skills)
      Bibliothèque signée de consignes : authentification (OIDC / SAML / LDAPS), règles IA, design system, règles du langage du projet.
      Arrêt d'urgence (kill switch)
      Bouton du RSSI ou de son adjoint : tout est gelé, les cellules détruites, les clés révoquées.
